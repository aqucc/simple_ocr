単一の `index.html`（Vue 3 ランタイム限定・`h()` render 関数のみ・テンプレート不使用）で完結。OCR は **PaddleOCR + ONNX Runtime Web** に一本化（Tesseract.js は廃止）。画像はサーバーへ送らず、保存は IndexedDB。

セクション: エンジン構成 / 文字検出 / 前処理 / ノイズ除去 / セキュリティ(CSP) / 依存 / 検証 / 既知の制限（右上の目次アイコンからも辿れます）。

## エンジン構成

| モード × 経路 | エンジン |
| --- | --- |
| 英数字(型番向け) × 範囲指定 | PaddleOCR PP-OCRv4（認識モデル、rec のみ） |
| 英数字(型番向け) × 全体 | PaddleOCR PP-OCRv4（DBNet 文字検出 → 認識） |
| 日本語+英数字 × 範囲指定 | PaddleOCR PP-OCRv3 japan（認識モデル、rec のみ） |
| 日本語+英数字 × 全体 | PaddleOCR（DBNet 文字検出 → PP-OCRv3 japan 認識） |

- **範囲指定（切り抜き）経路**は「人間の範囲指定＝文字検出」とみなし、検出モデル（DBNet）を省いて認識モデルのみを実行。範囲内が複数行なら水平射影プロファイルで行分割して1行ずつ認識。
- **「全体を読み取る」経路**は、まず DBNet で各テキスト行の枠を求め、各枠を切り出して同じ認識パイプラインへ通し、読み順（上→下、行内は左→右）に連結。検出0件のときは画像全体を1つの切り抜きとして扱うフォールバックあり。
- 認識セッションはモードごとにキャッシュし、モード切替時に非アクティブなモードの認識モデルを解放（iPhone のメモリ対策）。検出モデルは両モードで共有。
- ORT／モデルの読み込み失敗時は明確な日本語エラーを表示（Tesseract フォールバックは廃止済み）。
- ONNX Runtime は**シングルスレッド**設定（GitHub Pages は COOP/COEP を送らず `SharedArrayBuffer` 不可）、SIMD 有効・プロキシワーカー無効。
- 結果画面に使用エンジン名（例: `PaddleOCR (PP-OCRv4)` / `PaddleOCR (PP-OCRv3 · japan)`）を表示。

## 文字検出（DBNet / PP-OCRv4 det、OpenCV なし）

「全体を読み取る」で使う検出:

1. 画像の長辺を960px以下（各辺を32の倍数に丸め）へ縮小。
2. ImageNet の平均/標準偏差（RGB `(0.485,0.456,0.406)`/`(0.229,0.224,0.225)`）で正規化して det モデルへ入力。
3. 出力の確率マップを**しきい値0.3**で二値化。
4. 二値マスクをフラッドフィル（4連結）で連結成分に分解し、平均確率 ≥ 0.5・面積 ≥ 9 の成分だけ残す。
5. 各成分の軸並行バウンディングボックスを取り、`距離 = 面積 × 1.6 ÷ 周長` で外側へ拡張（unclip）してから元画像座標へ戻す。

ラベルはほぼ水平（微小な傾きは上流の自動傾き補正が処理）なので軸並行の枠で十分。

## 前処理（canvas）

PaddleOCR はカラー入力（PP-OCR 系は非二値化入力が前提）なので、認識モデルには切り抜き（傾き補正・台形補正済み）をそのまま渡す。

- 認識前の正規化: `(x/255 − 0.5)/0.5`・BGR チャンネル順・高さ48px固定（japan モデルは内部 reshape が高さ48を要求）。
- 行分割・単語分割・左右余白詰めはすべて純粋な canvas 処理。Tesseract 時代の二値化（局所適応しきい値・デスペックル）は不要になり削除済み。
- **自動デスキュー**（±12°）と**台形補正**（4点ホモグラフィ）は純JS実装。

### 傾き補正・台形補正

- **自動デスキュー**: 矩形モードの読み取り前に、±12°の範囲で候補角を走査し、行射影プロファイルの分散（シャープさ）が最大になる角度を推定して回転補正。|角度| < 1°なら省略。解析ラスタは約600pxに制限して高速化。
- **台形補正**: 切り抜きに「台形補正」モードを用意し、4つの角を独立にドラッグして輪郭に合わせると、射影変換（ホモグラフィ、8元 DLT をガウス消去で解く）で真正面の長方形へ逆写像（バイリニア）。モード切替時にラベルらしい領域を検出して角の初期位置を自動サジェスト（外れても手で調整可、検出失敗時は矩形の角にフォールバック）。出力サイズは `W = round(mean(上辺, 下辺))`, `H = round(mean(左辺, 右辺))` を `[16, 2000]` にクランプ。

### 単語レベルの自動分割

各行を列方向のインク・プロファイル（グレースケール＋大津の二値化）で走査し、単語間の空白を検出して単語ごとに個別の枠で切り出す。

- 分割しきい値: **英数字はギャップ長 ≥ 行高の45%**（最低3px）。文字間カーニングはこれを超えないため分割されない。
- 各単語は自身のインク行に応じて上下も詰め直し（余白15%を残してクランプ）、48px高さ正規化後に文字が大きく写るようにしてから個別認識・信頼度判定。**スコア0.5未満、または英数字モードで非ASCIIストリップ後に空の単語は破棄**し、行内の他の単語は生かす。
- 分割数が多すぎる場合（24個超、バーコード・模様の可能性）は分割せず行全体を一括認識。
- **日本語モード**は語間スペースが無いため、しきい値を行高の110%まで緩め、「定格 / 100V / 50Hz / 1.5A」のように明確に離れたフィールドだけを分割。連続する漢字かな（例: `東京都千代田区1-2-3`）は分割しない。
- 分割せず行全体を認識する場合は、まず左右の余白列を詰めて（`trimLineToInk`）から48px高さ正規化。余白の多い横長切り抜きをそのまま横に潰すと文字が欠ける（例: `50Hz` の `z` 落ち）ため、インク範囲だけを縮小対象にする。

効果: (a) 単語間スペースをCTCが安定出力しないケース（`MADE IN JAPAN`→`MADEINJAPAN`）を回避、(b) バーコード縞に隣接する数字だけを個別に救出。

### バーコードに強い行検出

行分割（水平射影プロファイル）のしきい値は、緩い絶対フロアで見つけた「候補ブロック」ごとのピーク値のうち**最も弱いブロックのピーク**を基準にする。バーコードのような単一の密なブロックが基準を釣り上げるのを防ぎ、候補が1つしかない通常の複数行ラベルでは従来と同じ挙動。

## ノイズ除去

### 信頼度による棄却（ハルシネーション対策）

行ごとの CTC 貪欲デコードで採用した各文字の確信度（非空白・非重複ステップの argmax 確率の平均。モデル出力は既に softmax 済み）が**0.5 未満の単語/行を破棄**。全行破棄なら結果は空文字列。

- 英数字モード: 辞書が中国語+ASCII のため、残った行からさらに非ASCII文字を除去（連続空白は1つに畳み込み、空行は破棄）。
- 日本語モード: 非ASCIIストリップは行わず（かな・漢字を残す）、全角→半角正規化のみ適用。

### 全角→半角の正規化（日本語モード）

保存対象が型番・住所であるため、日本語モードの認識結果は単語フィルタの前に全角ASCII（０-９Ａ-Ｚａ-ｚ）・全角ハイフン `－`・各種ダッシュ／マイナス・全角スペースを半角へ折り畳む（カタカナ長音符 `ー`（U+30FC）は保持）。これにより `1-2-3` や `KX-1234` が素の ASCII で保存され、数字トークンが単語フィルタの型番ルールに合致する。

### 単語フィルタ（ハイブリッド・トークン分類器）

信頼度の足切りをすり抜けるノイズ（認証マーク・ロゴの中の文字が孤立記号・単独CJK・無意味な短トークンとして残る）への対策。

**なぜ「辞書に載っている単語だけ残す」にしなかったか**: 型番・製造番号（`KX-1234AB` 等）は英単語ではないため、純粋な辞書フィルタはアプリの存在意義を消してしまう。そこで次のいずれかに該当するトークンだけ残す:

1. **英単語**: 小文字化して辞書に載っている（2文字以上、末尾句読点は除いて判定）。
2. **型番らしい文字列**: `/^[A-Za-z0-9][A-Za-z0-9\-\/.:#+]*$/` に一致し、数字を1文字以上含み、2文字以上（`KX-1234AB` / `5X-98765` / `100-240V` 等）。
3. **単位付きの数値**: `/^\d+(\.\d+)?(V|W|A|VA|Hz|kHz|mA|Ah|kg|g|L|mm|cm|°C)\.?$/i`。
4. **ラベル定型の略語ホワイトリスト**: `MODEL`, `MODELE`, `TYPE`, `SN`, `S/N`, `P/N`, `NO`, `NO.`, `LOT`, `REF`, `AC`, `DC`, `PSE`, `CE`, `FCC`, `MADE`, `IN`。

いずれにも該当しない（句読点のみ・無意味な短い記号列等）トークンは削除。

- **記号ノイズの除去**: 丸囲み英数字（U+2460–24FF）、丸囲み/角囲みCJK（U+3200–32FF、U+3300–33FF）、Letterlike Symbols（U+2100–214F）、Geometric Shapes（U+25A0–25FF）、Misc Symbols/Dingbats（U+2600–27BF）、および ®©™§※ を行ごとに一括除去してから判定。
- **CJK の扱い**: CJK文字どうしの間の空白は詰める。CJKの連続（ラン）を1単位とし、**ラン長2文字以上なら保持**（孤立した単独の漢字・かなは囲み文字誤読の典型として削除）。ラベル語彙の埋め込み辞書（型番・品番・型式・製造番号・定格・電圧・株式会社・日本製・取扱説明書・注意・警告など約80語）に含まれる／を含むランも保持。
- **EAN先頭1桁の例外**: 単独英数字トークンは通常2文字未満だと破棄するが、その行に数字が合計6桁以上ある場合に限り単独数字1文字を残す（例: `4 901234 567894` の `4`）。
- **UI**: 結果画面のテキストエリア上部に「単語フィルタ」トグル（既定 ON、`localStorage` 記憶）。タップでフィルタ後/フィルタ前（生の認識結果）を切替。全行が消えた場合は自動的に生テキストへフォールバックしトグルは OFF 表示。トグルはテキストエリア内容を丸ごと置換する（手動編集後に押すと編集は失われる）。

### 英単語リスト（辞書）

npm パッケージ [`word-list`](https://github.com/sindresorhus/word-list)（Sindre Sorhus 作、MIT）の `words.txt` を使用。

- 単語フィルタ初回使用時に `fetch()` → `split("\n")` → 小文字化して `Set` にキャッシュ（遅延ロード）。取得中は「辞書を読み込み中…」を表示。
- 取得失敗時は `console.warn` のみで、辞書チェックが常に `false` を返す「パターンのみモード」で継続（型番・単位・略語ホワイトリストは機能）。
- **JS の `Set`（WASMではない）を使う理由**: 27万語の完全一致ルックアップは `Set.has()` で O(1)・数MBメモリで十分高速で、WASM化のメリットが要求される規模ではない。

## セキュリティ（CSP）

`index.html` は厳格な CSP を `<meta http-equiv="Content-Security-Policy">` で指定。`'unsafe-inline'` / `'unsafe-eval'` は使わず、インラインの `<script>` と `<style>` は sha256 ハッシュで許可（WASM のため `'wasm-unsafe-eval'` のみ許可）。

```
default-src 'none';
script-src 'sha256-…(inline script)…' https://cdn.jsdelivr.net 'wasm-unsafe-eval';
style-src 'sha256-…(inline style)…';
img-src 'self' blob: data:;
connect-src 'self' https://cdn.jsdelivr.net data:;
worker-src blob:;
base-uri 'none';
form-action 'none'
```

- `script-src`: インライン script（ハッシュ）、Vue 本体、onnxruntime-web の遅延ロード（`<script>` 挿入）と内部の動的 `import()`（いずれも jsdelivr）、WASM 実行（`wasm-unsafe-eval`）。
- `worker-src blob:`: onnxruntime-web が内部で Blob URL の Worker を使う可能性に備える。
- `connect-src`: `'self'` は自己ホストの日本語モデル・辞書（`models/japan_rec.onnx` / `models/japan_dict.txt`、`fetch` 取得）用。`https://cdn.jsdelivr.net` は ONNX Runtime の `.wasm` / PP-OCRv4 検出・認識モデル・辞書、単語フィルタの `word-list` 取得用。`data:` は WASM の `data:` URI 取得用。
- `img-src`: 保存画像・プレビュー（`data:` / `blob:`）。

### CSP ハッシュの再生成

`index.html` のインライン `<script>` か `<style>` を編集したら必ず実行:

```
node tools/update_csp_hash.mjs
```

依存なしの素の Node が、インライン `<script>` と `<style>` の sha256 を計算して CSP メタタグの該当トークンを書き換える。

> デプロイ時、Pages ワークフローは `<title>` の直前に `<meta name="app-version" content="<コミットSHA7桁>">` を挿入する（インライン script/style の中身は変えないため CSP ハッシュに影響しない）。アプリはこれをヘッダに小さく表示し、ブラウザキャッシュに旧版が残っていないかを可視化する。

## 検証（自動テスト）

```
node tools/verify.mjs
```

Playwright + Chromium（プリインストール）で以下を確認する。**CSP 違反・JS エラーがあれば失敗**。

1. ローカル HTTP で `index.html` を配信して開く。
2. コンソール／ページエラーを収集。
3. 英数字ラベル画像（`MODEL: KX-1234AB` / `S/N 5X-98765`）を注入 → 切り抜きステージ表示 → 実ポインタで四隅を全体に拡大 → 「この範囲を読み取る」→ PaddleOCR で `/KX[-—_ ]?1234AB/i` と `/98765/` 一致、エンジン表示が PaddleOCR。
4. 「範囲を選び直す」→「全体を読み取る」→ DBNet 検出＋認識でも同テキスト一致、エンジン表示が PaddleOCR。
5. 保存 → 一覧で今日の見出し／カレンダーのバッジ → リロード後も永続（IndexedDB）。続けて「編集」→ テキストエリアに既存テキスト／他ボタン非表示 → 変更して「保存」→ 一覧更新 → リロード後も編集後テキストが永続。
6. 「日本語+英数字」モードへ切替 → 初回ダウンロードのヒント表示 → 画像注入 → 枠拡大 →「この範囲を読み取る」（japan 認識モデル）。CJK フォントがあれば `品番 AB-1234`（エンジン表示 PaddleOCR も確認）、無ければ ASCII のみ画像で成功を確認。受け入れゲート: `東京都千代田区1-2-3`（埋め込み数字が正確）、`定格 100V 50Hz 1.5A`（数値・単位が残る。単位の大小文字は既知の弱点のため大小無視で判定）、かなテスト `型番たしかめ 12-34`（ひらがなが ASCIIストリップされず残る＋`12-34` 正確）。
7. **ノイズ耐性ゲート**: 斜めグラデ背景＋約800個の砂嵐ノイズ＋ビネットの上にラベル文字を描いた画像（決定論シード）を、切り抜き→英数字／日本語の両方に流し、期待文字列一致に加え「期待文字列に無い英数字・CJK文字数（ハルシネーションの目安）」が英数字≤3・日本語≤6。単語フィルタのトグル機構（ON→OFFで生テキストに切替、生のガーベジ数≥フィルタ後）も検証。
8. **単語フィルタ（デコイ認証マーク）**: 丸囲み「R」・角囲み「検」・三角記号・`MODEL: KX-1234AB` / `S/N 5X-98765` / `MADE` / `JAPAN` を描いた画像を英数字経路に流し、`KX-1234AB` / `98765` / `MADE` / `JAPAN` が残り、単独1文字トークンが残らず、ガーベジ数≤2。
9. **単語レベル分割**: 広い間隔の `MADE     IN     JAPAN` 行を含む画像で、同じ出力行に `MADE` と `JAPAN` が含まれる（`IN` は認識揺れで欠けても許容）。
10. **バーコード隣接数字**: 縦縞40本のバーコード風ブロック直下の EAN 風 `4 901234 567894` で、`901234` / `567894` / 単独 `4`（EAN例外）が含まれ、ガーベジ数≤2（縞からトークンが残らない）。

> 補足: サンドボックスの通信ポリシーで `cdn.jsdelivr.net` が遮断されるため、検証時のみ jsdelivr へのリクエストを傍受し、`registry.npmjs.org` から取得した同一バージョンの npm パッケージ（`tools/.cdncache/`、Git 追跡対象外）で応答する。実ブラウザは jsdelivr から直接取得し、アプリ自体は改変しない。

## 既知の制限

- **オンライン必須**: Vue / ONNX Runtime WASM / PP-OCRv4 検出・認識モデル（初回約22〜27MB）は CDN 取得、日本語モデル・辞書（約10MB）は同一オリジン取得。いずれも初回はネットワーク越し（以後ブラウザキャッシュ）で、`file://` 直開きはモデルの `fetch` が失敗する。完全オフライン化には CDN 資産の自前ホスティングが必要。
- **日本語認識モデルの弱点**: PP-OCRv3 japan は、漢字に隣接した孤立大文字ラテン（`型番 KX` の `X`→`メ`）や単位の大小文字（`V`→`v`、`Hz` の揺れ）で誤りが出ることがある。数字・漢字・かなは良好で、住所・数値・かな・数字入り型番はカバー（結果はテキストボックスで編集可）。純粋な型番読み取りは英数字モードの方が高精度。
- 英数字モードの辞書は中国語+ASCII のため、まれに漢字ノイズが混じる（非ASCIIストリップで大半除去）。大きく斜めのラベルは自動デスキュー（±12°）と台形補正で補うが、範囲がずれると精度低下。範囲指定で読みたい行だけを囲むのが最も効果的。「全体を読み取る」の DBNet は極端な低コントラスト・過密レイアウトで検出漏れの可能性（その場合は範囲指定を推奨）。
- **保存容量**: 画像は最長800px/JPEG 0.7 に縮小保存するが、IndexedDB 容量はブラウザ依存。多数保存で上限に達する可能性。エクスポート機能なし。
- **クリップボード読み取り**は secure context（HTTPS/localhost）とユーザー許可が必要で、対応はブラウザ依存。
- **保存画像の EXIF** は描画時に向きのみ反映。位置情報等は保持しない。
- カレンダーは単月表示のみ。テキスト編集（`text` 上書き）はできるが、検索・タグ付けなどの管理機能はない。
- 検証は Chromium のみ（Playwright）。実機 Safari の自動テストは含まない。
- **単語フィルタの弱点**: CJKラン長のみの判定のため無関係な2文字以上のノイズを誤保持しうる／英語辞書は一般語で固有名詞は限定的／トグルはテキストエリアを丸ごと上書き（手動編集は失われる）／辞書取得失敗時はパターンのみモードで一般英単語が削除されうる。
- **単語レベル分割の弱点**: 単語間隔が狭い書体・詰め組み・筆記体風では未分割のまま（悪化はしない）／文字内に大きな空白がある装飾書体では過分割の可能性（24分割超はフォールバックするが、それ未満の誤分割では断片が個別判定され本来1単語が欠けることがある）／EAN単独数字の例外は行に数字6桁以上あるときのみ。
