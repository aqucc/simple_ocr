## 認識ダイアログ

撮影・選択すると、撮影／一覧タブを持たない**認識ダイアログ（モーダル）**が開きます。認識は独立したタスクとして全画面で行い、右上の **✕** はキャンセル（＝入口へ戻る）です。撮影から入れば保存で新規レコード、一覧の「再読み取り」から入れば上書き保存になります（[再読み取り](#記録)参照）。

## 認識モード

用途に合わせて2つから選びます。選択は認識ダイアログ（切り抜き画面）で行い、`localStorage` に保存されて次回も復元されます。撮影前ではなく読み取り直前に選べるので、同じ画像を両モードで読み比べるのも簡単です。

- **英数字** — 型番・製造番号・シリアル等の半角英数字に最適。最も高精度。
- **日本語** — 住所・品名など和文を含むラベル向け。半角数字（`東京都千代田区1-2-3` の `1-2-3` など）もそのまま読めます。

結果画面には実際に使われたエンジン名が表示されます。

## 範囲指定と補正

### 矩形モード
枠内だけを認識します。**読みたい行だけを囲む**のが精度向上の最大のコツです。読み取り時、±12°の傾きは自動で水平化されます。

### 台形補正モード
斜めから撮った写真向け。四隅を独立に動かしてラベルの角に合わせると、正面から見た長方形に引き伸ばしてから認識します。モードに入った時点で、ラベルらしい輪郭を推定して四隅を自動配置します（合っていなければ手で調整）。

### 全体読取
枠を使わず、画像から文字行を自動検出して各行を認識し、上→下・左→右の順に連結します。過密・低コントラストなラベルでは検出漏れが起きることがあり、その場合は範囲指定が確実です。

**キャンセル / 指定範囲読取 / 全体読取** の3ボタンは横1列。読取アクション（指定範囲読取＝実線、全体読取＝アクセント枠線）は有色、キャンセルは無彩色です。結果画面も **キャンセル / 再読取 / 保存** を横1列にして、テキスト欄を広く取ります。

## 単語フィルタ

認識のあと、ノイズや誤読を落とすフィルタです。結果画面のトグルで**オン/オフを即切替**でき（既定オン・記憶あり）、生の認識結果と見比べられます。

残すのは次のいずれかに当てはまるトークンだけです。

- 英単語（辞書照合）
- 型番らしい文字列（数字を含む英数字・記号列。`KX-1234AB` など）
- 単位付きの数値（`100V` `50Hz` `1.5A` など）
- ラベル定型の略語（`MODEL` `S/N` `LOT` など）

認証マーク（丸囲みR、角囲みの検印など）の中の文字といった記号ノイズは除去されます。バーコード直下の数字は、隣接する縞に巻き込まれず個別に拾います。

> フィルタで全部消えてしまった場合は自動的に生テキストへ戻ります（結果が悪化しない設計）。トグルはテキスト欄を丸ごと置き換えるため、手動編集後に押すと編集は失われます。

## 記録

保存すると、写真（縮小 JPEG）と認識テキストが端末内（IndexedDB）に残ります。

- **カレンダー（一覧の入口）** — 一覧タブを開くとまずカレンダーのみを1画面表示。記録がある日にはバッジ（件数）。
- **日ビュー** — 日をタップするとその日の記録一覧へ。上部に「‹ カレンダー」（戻る）と「この月の記録」（カレンダーで表示中の月の記録を日毎リストでまとめて表示、新しい日が上）。別の月を見るにはカレンダーに戻って ‹ › で移動します。
- **項目内のグループ化** — 操作対象ごとにまとめています。**写真**（左カラム）はタップで拡大、その下の**再読取**は同じ画像の読み直し。**テキスト**（本文）の下に**コピー**と**編集**。**削除**は項目自体の操作なので右上に ✕ で独立配置。
- **テキスト編集** — 「編集」でその場で修正。同時に編集できるのは1件のみ（別を開くと未保存の変更は破棄）。編集中は再読取／コピー／編集／削除は隠れます。
- **再読取** — 保存画像で認識をやり直します。範囲やモードを変えて読み直し、**上書き保存**すると元の記録をその場で更新します（カレンダーに新しい記録は増えません／キャンセルで一覧に戻ります）。保存画像は縮小版のため、元写真より解像度は低めです。

## 基盤・プライバシー

- OCR も保存もすべてブラウザ内で完結し、**画像はサーバーへ送信されません**。
- OCR は PaddleOCR（検出 DBNet ＋認識）を ONNX Runtime Web（WebAssembly）で実行。
- 厳格な CSP（`unsafe-*` 不使用）で動作。
- 初回のみモデルの取得に通信が必要（以後はブラウザキャッシュ）。`file://` 直開きではモデル取得に失敗します。

## 既知の弱点（かんたん版）

- 日本語モデルは、漢字に隣接した孤立大文字ラテン（`型番 KX` の `X` など）や単位の大小文字で誤りが出ることがあります。型番だけなら英数字モードが確実です。
- 詰まった書体では単語の切れ目を検出できず、まとめて認識されることがあります（悪化はしません）。
